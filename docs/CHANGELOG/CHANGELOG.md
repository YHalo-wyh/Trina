# Trina 更新日志

## 0.5.0 · 2026-11-20 · Rust 原生只读工具层

- 新增 `native/` Cargo 工程和 `trina-native` 二进制，提供 Rust 文件读取与固定字符串检索原语。
- `workspace_read`、`workspace_read_many` 和固定字符串 `workspace_search` 会在 Rust 二进制可用时使用原生实现，缺失时自动回退到原有 Python 实现。
- Python `ToolRegistry`、ScopeGuard、动作等级、审计、超时和证据链继续作为唯一控制边界；终端执行、网络、写入和编辑不由 Rust 绕过授权。
- 包版本、首页版本和机器规约升级到 `0.5.0`。

## 0.4.0 · 2026-11-20 · 题目文件型 CTF 路由收窄

- 新增题目文件型 CTF 动态路由，首条任务合同要求批量读取题面、源码和验证器，避免重复 `pwd/ls`、切片读取和无效探针。
- 新增 `workspace_read_many`，一次返回多个短源码文件，避免正文被字段平均截断后触发重复 `sed`；该路由只向模型暴露终端和工作区工具，权威验证器仍通过 `terminal_exec` 进入最终状态判定。
- 有明确漏洞类或路径目标时才恢复事实登记和目标台账工具，没有可解析硬性目标且没有注册检查项时移除 `list_goals` 与 `prove_goal`。
- CTF 文件路由的原生工具调用改用紧凑 Schema，保留标准 API 的类型、必填项、枚举、默认值和依赖字段，减少重复参数说明带来的输入 Token。
- 对当前目录中明确存在的题面、源码和验证器增加一次受控首轮预取，仍经 ToolRegistry、范围检查和审计；嵌套 `subprocess.run` 调用验证器并返回独立 `OK` 时也会进入权威回执链。
- 题目文件路由和权威校验识别扩展为文件名无关的校验语义，覆盖任意 Python 题目文件配合 checker、validator、verify 或 validate 入口，并保留不同文件布局的回归测试。
- 增加题型路由与工具白名单回归测试，保留通用 Web、Binary、Crypto 和 Forensics 路由行为。

## 0.4.0 · 2026-11-19 · Agent 请求与事件流加速

- 对话首轮沿用本地确定性标题，不再额外占用一次在线模型请求。
- Chat Agent 复用按题型裁剪后的原生工具 Schema，减少重复构造。
- 运行事件 SQLite 使用 WAL + NORMAL 同步和内存临时表，降低思考、正文与工具事件的落盘等待；授权审计链继续使用独立的持久化路径。

## 0.4.0 · 2026-11-19 · Binary 路由收窄

- Binary/Pwn/Reverse 任务默认移除 Web 搜索、浏览器、HTTP 测试和 Web 漏洞工具 Schema，保留终端、工作区、r2/GDB、事实与结果工具。
- Binary 路由提示词要求批量完成静态检查、复用已确认事实，并把利用脚本作为一次可复现工件运行，减少无关模型轮次。
- Binary 路由进一步隐藏目标清单、仓库管理和 Worker 管理工具，并在连续无新事实后推动模型进入利用验证。

## 0.4.0 · 2026-11-19 · 按需工具 Schema 与 CTF 工具裁剪

- Agent 不再向模型注入完整内置工具 Schema。按题型动态绑定 CTF 核心工具，Binary、Web 深度工具和浏览器能力按任务加入。
- 增加执行白名单，隐藏的企业资产图、交通证据重型链、重复终端控制和高风险快捷工具不能仅靠模型猜名调用。
- 工具模块与 Capability Runtime 仍保留，显式能力租约和自定义注册表不受默认 CTF 裁剪影响。

## 0.4.0 · 2026-11-19 · Web 搜索与统一引用

- 新增独立 `web_search` 工具，支持 Google/Bing 免费路径和 DeepSeek 官方 Search API 适配器。
- 支持 `site:`、`after:`、`before:`、`filetype:`、`language` 等条件，结果统一为结构化条目、`[n]` 引用、来源和交通证据。
- 搜索请求沿用 `ctx.http`、ScopeGuard、限速、审计和结果压缩，不把搜索摘要自动登记为已验证事实。

## 0.4.0 · 2026-11-19 · CTF 目标解析与题目目录读取

- 控制台底栏移除聊天轮次显示，模型、角色、缓存和 Token 保持原有布局；内部轮次计数继续用于会话恢复、调度和评测统计。
- `trina bench` 不再暴露 `--attempts` 轮次选项，续做由现有 Commander、进展和时间预算自动决定；环境变量与内部状态字段继续兼容旧检查点。
- `GoalRequirements` 只从 `port:数字`、`端口:数字` 和明确的 `host:port` 提取端口，忽略 `AUTHORED-*`、UUID、普通数字串及文件路径中的数字。
- `scope.allow_paths` 支持以 `/**` 声明递归 CTF 题目目录，文件读取继续经过路径解析、符号链接收敛和审计。
- CTF playbook 规定 `--goal` 使用短合同，题目 ID、实例、目标和提交命令从 `CTF_GOAL.md` 通过 `terminal_exec` 读取。

## 0.4.0 · 2026-11-19 · 动态题型路由与 Worker 结果契约

- 系统提示词新增任务级题型路由。Agent 根据目标语义、附件路径和工具快照在首条任务合同中选择 Web/API、Binary/Pwn/Reverse、Crypto、Forensics/Stego、Code/Repository 或 General 指引，稳定 system 前缀保持不变。
- 原生工具合同明确批内调用按顺序执行，`_depends_on` 只表达本批次前序依赖，避免模型误把批量提交当成并行执行。
- Swarm Worker 统一返回版本化结果契约，包含 `status`、`verified_facts`、`evidence_refs`、`failed_paths`、`remaining_questions` 和 `artifacts`。Worker 异常退出时也返回结构化失败结果。
- 新增题型路由、原生批量语义和 Worker 失败契约回归测试，更新提示词说明文档。

### 2026-11-17 · Playwright 浏览器与本机逆向工具

- 新增 7 个 Playwright CLI 注册工具，覆盖浏览器打开、可访问性快照、结构化交互、Cookie/Storage、请求/响应证据、截图和关闭；会话按任务隔离，完整输出落工作区，恢复不复活进程。
- 外部执行边界支持唯一显式的受管子进程保留，用于浏览器启动；超时、取消、租约释放和任务结束仍回收。浏览器在 restricted 模式明确禁用，避免跨源子资源绕过逐 URL 裁决。
- `trina doctor` 展示 Node/Playwright 入口；本机验证固定版 Playwright CLI、Chromium、radare2 6.2.6 与原有 10 个 r2/GDB 工具。

### 2026-11-17 · 主动并发与临时任务模块

- Commander 遇到两个及以上互不依赖的交付物、目标或验证分支时，明确要求主动提交多个 `worker_tasks(spawn)`；Swarm 仍按真实依赖和并发额度调度，不为单步小事制造 Worker。
- 移除核心中的 CTFY 命令、工具、运行器、镜像和专用提示词。靶场/比赛平台改用仓库外 Capability 包；清单同目录 `AGENT.md` 在任务租约建立时 JIT 加载，只进入 user 任务合同，不注入 system。

### 2026-11-16 · 动作预算收尾与输出自动尾随

- Chat 单条消息耗尽工具动作预算后，追加一次不携带 tools 的标准模型请求，基于已经取得的真实观察生成阶段性结论；不再用“回复继续”占位替换本应交付的结果。外部 Harness 可用通用硬预算标志禁止展示性总结调用。
- 内容区改用显式尾随状态：正常流式正文和工具更新自动保持最新一行可见；用户主动上滚时冻结历史位置，下滚到底、`Ctrl+End` 或发送新消息后恢复。残留文本选区不再误判为历史锁定。
- 新增工具预算总结和尾随/历史锁定回归，设计取舍见 ADR-0036。

### 2026-11-16 · 仓库工作流、rg 与完成提醒

- `workspace_git` 扩展为仓库级工具：状态、结构化 Diff/历史、显式暂存与撤销、提交、分支、远端 fetch/fast-forward pull/non-force push，以及干净 worktree 的创建、列出和移除。`/repo`、`/branch`、`/worktree` 共用同一注册和审计链。
- 新增 `workspace_search`，优先调用真实 ripgrep，统一返回文件、行号、列号与匹配文本；缺失时跳过版本库、依赖、大文件和二进制做有界降级。Bash 继续由 `terminal_exec` 的 argv 模式执行。
- 新增 trina/contrast/mono 语义配色，运行、成功、警告、失败和 Diff 行按真实状态着色；`/theme` 即时切换。
- Agent 轮次和后台任务终态新增短时终端通知条，并按终端能力发送 OSC 9/99 或 BEL；`/notify on|off|test` 和 `ui.completion_notify` 控制完成提醒，重定向输出不注入控制序列。
- 机器规约补充 TR-03-R09、TR-05-R05 与 TR-05-R06，设计取舍见 ADR-0035。

### 2026-11-16 · 直接样式片段与输出性能复测

- CommonMark 正文直接生成终端样式片段，代码高亮使用有界行缓存，跨行语法保留整块处理；稳定后续块不重复排版。工具窗口按帧线性排版，非全屏输出保持 Unicode 折行。
- 显示调度间隔改为 1/120 秒，静态主题取消空闲周期刷新；支持的终端对相同重叠行搬运滚动区。主界面挂起时拒绝迟到读键回调，避免抢走弹窗确认键。
- 同机同流 18 轮复测：短/长历史/四路输出 P95 为 16.0/19.3/15.9ms，OMP 为 34.9/33.5/21.0ms；工具流 28.6/35.6ms。CPU 与滚动仍有差距，模型、网络和完整解题未计入。旧基线保留，最终数据与画面见 `评测/20261115-omp-output-benchmark/optimization/`。
- TR-22-R05 补充可机器验证的内容、稳定块缓存、延迟排版、Unicode 和弹窗输入契约，设计取舍见 ADR-0034。

### 2026-11-15 · OMP 同机同流输出评测

- 新增固定 120×36 Kitty VT 引擎、40ms 输入回放和三轮交替执行的生产 UI 对照，覆盖思考/正文/工具、120K 历史与四路活动块，共 18 轮。
- 实测短输出可见延迟 P95 为 Trina 130.7ms、OMP 34.9ms；长历史为 342.8ms、34.4ms。当前渲染尚未同级，Trina 进程内存较低。模型、网络、GPU 和真实 Worker 调度未计入。
- 评测目录保存锁定依赖、逐帧结果、覆盖率、画面及复算脚本；生产运行时保持不变。

### 2026-11-15 · 低延迟流式输出

- 参考 OMP 的活动块更新与按帧调度，模型增量合并后持久化；首块立即显示，空闲尾部、结束与异常强制刷新。已提交的连续本地事件直接投递，缺口仍持久重放。
- 模型实际返回的思考单列低亮度块，正文持续输出；工具窗口原位更新，仅显示帧排版。子 Worker 四宫格接入独立思考/正文流，最终消息不重复。
- 修复代码围栏和代码内字典导致正文等待到结束的问题，保留 JSON/DSML 工具协议过滤。新增真实本地 SSE 在 DONE 前可见、增量不丢失、异常尾部与卡片延迟排版测试。

### 2026-11-15 · 事实驱动探索与跨轮续做

- 新事实通过有界 `FactIntentPlanner` 生成现有 Intent：支持资产、已验证发现与凭据，继承能力/模型/范围，按显式来源去重并保留依赖。CLI Swarm 与子 Worker 默认开启，可用 `--no-auto-expand` 关闭；Bench 保持题目容器独占。
- Bench 默认最多两轮，共享单题墙钟预算；续轮继承结构化事实、证据、步骤及累计用量，重新建立模型消息和工具上下文。无新增进展或停止/阻断时释放 Worker。
- 输出每轮模型决策、调用、工具、重复探索率和真实耗时；真模型跑批增加 Ledger/Loop Guard 消融配置，方便在同模型、题集和预算下比较。离线回归不作为线上解题性能结论。

### 2026-11-15 · 执行内核收敛

- Agent/Chat/Worker 收敛到一个 `AgentRuntime`；原生一轮多个工具调用全部执行，支持 `_depends_on` 前序依赖并为每个调用保留标准回执。批内顺序执行，不把共享状态变成并发竞态。
- 默认 CTF 路径改为目标驱动，关闭固定 PTES 阶段和逐步假设调度；旧模块可显式启用。状态检查点默认每 5 个动作一次，新增事实仍立即保存。
- Swarm 的 Intent 成为唯一任务状态，TaskRecord 改为字段视图；检查点 v4 删除重复 records，并兼容迁移 v1–v3。Todo、探索图和证据图作为派生视图。
- TSecBench 题目复用同一 Task Scheduler/Worker Pool，默认并行 2、上限 3；每题独立控制面会话并保证容器回收，平台 submit 回执仍是唯一成功判据。
- 核心运行状态清洗移出终端展示模块；请求尾部状态栏使用紧凑投影，完整真实快照仍写入 RunState。

- 新增 `/subworker` 实时任务面板：名称/目标/状态、独立模型与思考强度、实际调用和 Token；支持新任务默认设置、等待任务修改、后台并行、追加/去重、暂停/继续、停止和恢复。模型与供应商选择不改主会话。

## 开发中 · 2026-11-13

### Agent 协作运行时与编码能力

- 参考 ARTEX 的事件唤醒、Todo、Intent 生命周期和 Worker Trace 思路，在现有 `SwarmRuntime` 外加入轻量 `CoordinationRuntime`：Planner 只响应图变化，普通 Worker 步骤不触发主规划。
- 新增持久共享 Todolist、带稳定签名去重/优先级/依赖/租约/超时回收的 Intent 队列，以及事实图与探索图双图；检查点升级到版本 3。
- Worker Trace 记录真实工具观察、错误和 Intent 生命周期。相关 Worker 可复用带来源的成功观察与失败经验，但每题 `RunState`、完整消息和事实判定仍隔离。
- 新增 `terminal_exec`、`workspace_read/write/edit` 四个编码工具，以及 `shared_context`、`shared_trace_search/get` 三个协作查询工具；注册工具总数由 31 增至 38。
- Chat Agent 改为优先使用标准 API 原生 `tools` / `tool_calls` 并维护工具消息配对；修复网关把 DSML 分隔符扩成 `< | | DSML | | ...>` 后被当作最终正文的问题。

### radare2 + GDB 原生工具链

- 新增 10 个 ToolRegistry binary 工具，使用 r2 stdio JSON 与 GDB/MI3 持久会话；支持静态索引、PIE/ASLR 地址转换、断点、寄存器/内存/帧、文本 stdin、候选执行与结构化错误。
- 会话按任务和能力租约隔离，Linux 默认经 bubblewrap；超时、租约释放、关闭和恢复时回收原生进程。完整协议写入证据，模型只接收分页摘要与引用。
- Binary Role 同时接入 JSON/native 与两种提示词分层路径，不把通用 Worker 固定成逆向流水线。真实 ELF 回归覆盖多 Worker、异常退出、超时、ASLR、恢复失效及正确/错误候选。

### 模型窗口

- `context_window=0` 改为按模型自动：DeepSeek 500K，明确识别的百万窗口 GPT/Claude/Gemini 为 1M，未知型号 32K；`/model context` 和供应商表单支持手动设置并持久化。
- 新增 ADR-0026、二进制工具和模型上下文文档，机器规约增加对应实现与测试引用。

### 历史对话与 /resume

- `/resume` 改为搜索、查看和切换历史聊天；支持列表、最近会话、编号、完整 ID 和唯一前缀。暂停任务改用 `/unpause`，运行中仍可 `/resume list`。
- 聊天自动保存至项目工作区 SQLite，退出后恢复标准消息、事实、台账、压缩检查点、预算和累计用量；切换保留输入区与草稿，工具记录独立排版。
- 事务失败保留旧快照；先锁定再读取，防止并发实例覆盖；已有审计链损坏时拒绝恢复。恢复沿用当前模型及执行配置，不重放工具或复活后台进程。
- 旧版本未保存完整回复的历史无法重建。新增机器规约 TR-03-R05、回归用例及 ADR-0025，验收结果见历史会话验证记录。

### 缓存感知上下文

- 事实、检查项和台账改为状态差量，周期发送完整检查点；动态计时继续留在尾部 Agent 状态栏。
- 新增上下文预算和自动继承检查点，原始消息先原子归档，用户约束、事实、证据索引及最近执行链继续保留；归档失败不删除历史。
- 按供应商协议适配缓存字段，未知中转显式声明能力后协商；缓存参数被明确拒绝时最多降级一次，供应商切换不携带其他连接的能力声明。
- `/context` 查看前缀变化、预算和真实缓存用量，`/compact` 手动压缩；不根据字节相同推算服务端命中，不公布未实测的缓存收益。

### 滚动性能、复制与模型状态栏

- 对照 Oh My Pi 的“稳定历史与可变视口分离”后，视口改为按脏块一次性完成 ANSI/Unicode 物理行折行，关闭 `prompt_toolkit` 二次折行；支持 VT 的终端用 SU/SD 滚动区域搬运不变行并同步旧屏缓存，下一帧只补新露出的行，其他终端保持安全降级。
- 修正最早历史位置多出一整屏无效滚动范围的问题；到达上下边界后不再提交无画面变化的重绘。
- 会话内容改为按块缓存排版行，滚动和活动动画不再扫描全文；流式增量合并到实际绘制帧，只更新变化块。
- 支持鼠标拖选中文与多行文本，释放后复制；Ctrl+C 在有选区时复制，Esc 清除，F2 切换终端原生选择模式。
- 新增独立的模型 Agent 状态栏，在每次请求末尾追加真实进度、工具计数、环境观察及后台作业快照，保留既有结构化消息前缀。
- 新增终端启动、查询、等待和取消工具。后台作业按任务隔离，有超时、并发与输出上限；使用 POSIX 进程组或 Windows Job Object 回收进程树，默认不继承模型密钥。

### 标准 API 与流式输出

- 删除 OMP 模型后端、独立模型数据库和 `/backend` 命令；供应商地址、Key、模型及思考设置统一由 `/model` 管理。旧 `omp_model` 字段不再参与启动，下次保存时删除。
- Agent 发送标准角色消息，保留 assistant 与工具观察；system 和初始合同固定，动态状态只追加，避免重新拼接历史导致角色边界与缓存前缀变化。
- Chat Completions、Messages、Responses 采用各自 SSE 方言；正文卡片原位更新，终止事件、截断及错误有独立检查。JSON/DSML 和隐藏思考不作为正式答复。
- 无 TTY 保持一次完整输出，健康检查与表单验证保持短请求。随后已加入确定性的继承检查点；缓存统计仍只采用供应商真实返回。

### Capability Fabric

- 用 Catalog、Broker、Runtime 三模块统一发现 Tool、CLI、MCP 能力，按任务签发 TTL 租约并固定版本快照，工具 Schema 与 Guidance 按需加载。
- 通用 Worker 可在任务间切换能力，释放后旧租约失效；跨任务共享证据索引与相关情报，事实图及完整对话保持独立。
- 删除固定 recon/web/review 咨询实现和旧开关，保留通用失败、原子快照及调度测试；默认任务改为单个通用 main，显式 DAG 决定并行研究。
- 修复重复发现回显、未验证 TLS 警告干扰终端、HTML 标题实体和泄漏 DSML 协议的展示问题。

实现限制：当前 MCP stdio 按调用启动与回收，尚无常驻 MCP 服务池或操作系统级沙箱。设计依据见 ADR-0021、ADR-0022。

### 会话记录滚动

- 主控制台启用鼠标滚轮和触控板滚动，保留 `PageUp` / `PageDown`，并增加逐行滚动、跳到最早记录和回到最新输出的快捷键。
- 用户上翻历史后锁定阅读位置；后台新增回复不会把视口强制拉回底部，活动栏明确提示如何返回最新内容。
- 滚动状态继续由持久内容区管理，不影响底部输入草稿、命令索引、模型状态和会话用量。
