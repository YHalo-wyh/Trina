# Trina 问题框架

## 背景、问题与结果

Trina 面向课程授权靶场的自动安全测试。操作者需要从一个地址和任务描述开始，获得可解释的侦察、验证和报告结果。现有实现已经提供 CLI、ReAct 主控、17 项目标分析工具、可选专职咨询、靶场适配器和审计报告。项目当前的问题包含两个层面：执行时需要限制模型动作并坚持证据判定；交付时需要让仓库中的需求、实现和证据形成可检查的联系。

执行层的失败代价是错误目标访问、把探测线索报告为已验证漏洞、重复调用耗尽预算，或把未检测到写成全局安全。工程层的失败代价是维护者和教师只能阅读功能介绍，无法确定哪些能力已实现、何时算完成、失败后怎样恢复。本次补齐规格与 Harness 文档，保留已有实现和原始验证事实。

期望结果是：给定授权目标与测试任务，主控提出可解析动作；执行链独立校验目标、工具和动作；工具结果形成状态及报告；复核者能定位证据、未覆盖项和停止原因。对课程交付，抽查一条 `REQ` 即可继续追到场景、任务、测试与事实文件。

## 目标、非目标与成功判断

| 对象 | 具体约定 |
|---|---|
| 目标 G1 | 合法动作能够经过现有执行链产生结果；越界和坏参数在对应关口拒绝，测试检查工具或传输层未被调用 |
| 目标 G2 | 漏洞、任务成功和运行结论依据工具事实分别计算，失败与未测部分可见，模型自报结果不代替验证 |
| 目标 G3 | 用同仓库的稳定 ID、命令和证据支持教师抽查，交接者能够复现机械检查及固定决策端到端验证 |
| 非目标 NG1 | 本次不重写扫描器、授权控制器、模型框架或注册表，不改变已存在的范围和等级配置 |
| 非目标 NG2 | 不建设多人 Web 管理平台，不增加账号、租户、云部署或论文评审业务 |
| 非目标 NG3 | 不以本地通过用例证明通用漏洞零误报，不宣称达到官方 TSecBench 成绩，也不以多角色数量证明性能提升 |
| 成功判断 | 文档检查通过；实际回归结果原样留存；两轮新靶机的执行机制可复现；人工审查状态明确，缺口有负责人角色与关闭条件 |

## 范围、约束和不变量

本次修改范围是课程文档、仓库导航、追踪清单、文档检查脚本和精选证据。产品基线包含 `trina/`、`configs/` 和 `tests/`，仅用于核对与验证。Python 版本要求为 3.10 及以上，优先使用已有依赖和内置靶机，不把付费模型或 Docker 作为教师检查文档的前提。

保持的不变量包括：I1 模型文字不能扩大配置授权；I2 目标工具仍通过注册表及既有目标访问出口；I3 模型 `final` 不能直接生成 flag 或已验证发现；I4 结论须保留证据、失败及覆盖限制；I5 历史审计原文保留，不能为展示修改哈希链；I6 不把运行中的聊天、机器摘要或未签署意见当作人类批准。

## 利益相关者与冲突处理

操作者希望少配置、尽快取得结果；复核者需要足够信息解释行为；维护者需要避免重复定义和文档漂移。项目通过默认预算、结构化结果、渐进资料入口和追踪检查协调这些目标。展示简洁不能以删除失败证据为代价，追踪完整也不要求把全部原始响应放进 README。授权配置冲突回到配置和控制器，规格冲突回到经维护者确认的版本，课程评价交由教师。
