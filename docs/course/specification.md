# Trina 需求与规格

版本 `1.0`，日期 2026-10-21，适用代码基线 `24fb637`。需求来源为 [INT-01 / INT-02](intent.md)。本文件规定可观察行为；实现位置、测试和任务的对应关系见 [验收矩阵](acceptance-matrix.md)，具体初始状态及断言见 [场景卡](scenarios.md)。

## 术语与规范强度

大写 `MUST` 表示本规格的强制要求，`MUST NOT` 表示禁止行为。`SHOULD` 表示原则上采用，偏离时记录理由。`MAY` 表示可选能力。每条强制要求都有验证入口；入口存在与实际通过是两种状态，教师的最终接受也单独记录。

“主控”指 `PentestAgent` 或对话入口 `ChatAgent`；“控制器”指 `AuthorizationController`；“护栏”指 `ScopeGuard`；“注册检查项”指靶场配置中的 `test_id`；“发现”指 `Finding`；“证据”是工具保存的响应、命令结果或其他实际观察。“模型建议”“已允许动作”“已验证漏洞”“任务成功”和“课程验收通过”分别具有不同判据。

## 一、输入、授权和执行

### REQ-01 任务输入与动作协议

系统 MUST 接收明确目标及可选任务目标，在调用工具前把模型输出解析为一个候选动作或结束声明。动作使用 `action` 和对象类型 `params`，可附 `test_id`、`hypothesis` 等协议字段。允许从围栏 JSON 或附有解释的文本中恢复合法对象，恢复失败应形成错误观察，随后受步数与时间预算约束继续或收尾。

配置输入来自文件与已有覆盖接口；未知配置项不能被静默解释成新能力。模型输出垃圾文本不应被当作 Shell 执行，`final.status` 也不能修改已验证事实。验收观察是解析对象、错误反馈和实际调用次数。输入协议测试只能证明解析和恢复，不能证明自然语言任务永远不存在歧义。

### REQ-02 目标范围的确定性裁决

系统 MUST 在任务预检及目标工具实际访问路径上，按有效 `ScopeConfig` 检查目标。默认授权回环和 RFC1918 私网，公网开关关闭；显式拒绝网段、特殊地址及域名解析结果按护栏实现裁决。越界的任务预检 MUST NOT 调用模型，越界工具动作 MUST NOT 进入被保护的目标操作。

拒绝需给出原因和可供主控调整路径的反馈，相关动作通过现有审计路径留痕。验收采用测试夹具中的调用计数，不能为了证明拒绝而实际请求公网地址。该要求针对 Trina 的执行边界，不代表宿主操作系统已经提供隔离容器或对所有第三方进程实施系统级出网封锁。

### REQ-03 注册检查项与撤权

在非空注册表的 `strict` 策略下，控制器 MUST 拒绝未注册目标、缺少或不存在的 `test_id`、`test_id` 与工具不匹配及不属于对应目标的检查项。撤权后，后续命中该注册目标的动作 MUST 被拒绝。`guided` 允许按工具和目标反查注册项，未注册动作继续接受范围护栏检查，并记录未注册情况；`free` 不承担 strict 的注册约束。

`configs/ranges/*.yaml` 保存目标和检查项，模型只有引用权。当前实现的裸主机继承和参数匹配存在局限：不能把 strict 描述为完整参数模板约束或对同主机任意端口的绝对隔离。具体风险见 OQ-02。验收至少检查策略决策、拒绝原因、撤权记录和工具不执行，不能仅观察提示词中出现了“只用注册项”。

### REQ-04 工具统一契约与错误隔离

目标工具和可选咨询工具 MUST 注册为 `Tool`，声明 `ToolSpec`、参数表及动作等级，由 `ToolRegistry.execute` 统一执行。未知工具、未知参数、缺失必填参数、无效枚举和无法转换的类型应返回结构化错误；允许的类型转换以现有参数契约为准。

工具返回 `ToolResult`，包含成功状态、摘要、数据、事实、证据和后续提示等字段。实现异常及超时应转为错误结果，保留可解释的失败并避免导致整个流程因未捕获异常退出。工具超时返回不等于后台线程已被强制取消，强取消属于 OQ-03。该要求通过真正经过注册表的坏参数、抛错和超时夹具验证。

### REQ-05 动作等级与高风险参数

系统 MUST 依据本次参数的有效等级检查 `detect < verify < exploit`，默认上限为 `verify`。破坏性动作还受单独开关和主机列表约束，硬禁止参数不因提高等级自动开放。目标工具 MUST 使用已有 HTTP 或外部进程包装器，不能通过模型生成另一条未审计的目标执行路径。

动态等级用于区分少量显式凭据验证和大规模字典尝试，单凭工具名不足以判定风险。验证应覆盖等级拒绝、破坏性开关、爆破规模和 HTTP 查询中的危险 payload。该要求不承诺仅靠字符串规则识别全部语义等价攻击，扩展的协议和编码需要对应测试。

### REQ-06 HTTP 重定向与重试语义

HTTP 客户端 MUST 对后续跳转重新检查地址、方法和 payload，禁止跨源跳转向未批准目的地继续发送。相对跳转应保留实际终点和历史；303 按实现转换为 GET，307 保持方法及表单语义。重定向循环必须有界，关闭跳转选项应生效。

传输失败时不能盲目重试有副作用的 POST。只读请求允许按客户端策略有限重试。验收在回环测试服务器与 mock transport 上检查目的端命中次数、最终 URL、方法和请求体，不能以页面最终能打开代替跳转边界检查。该规范不定义通用浏览器跨域授权机制。

## 二、事实、判断与人机协同

### REQ-07 发现与证据的关联

系统 MUST 将工具事实与模型提出的假设分开保存。假设的确认需要同验证对象相符且带证据的发现，不能由相同漏洞类但不同 URL 或参数的观察确认。同一发现状态升级时应合并证据，后续超时不能抹去已确认的证据。仅反射输入、固定错误页或静态文件特征不能直接升级为对应漏洞已验证。

验收同时包含正例、阴性对照及重复观察，包括命令随机标记、SQL 错误对照和 LFI 缺失文件对照。`verified` 仍是可信工具给出的结构化判断；目前没有对所有发现运行独立复现器，因此测试通过不能提升为“所有工具判断绝对正确”。

### REQ-08 任务成功与结论三分类

系统 MUST 根据实际状态计算任务结果，模型 `final` 中的 flag、发现和成功文字只能作为声明。显式漏洞、路径或端口目标未满足时，不得因取得另一个 flag 而自动宣称该目标完成。任务运行状态与报告结论独立保存：有证据的已验证发现可形成 `CONFIRMED`；没有注册项执行、存在错误、失败、撤权或拒绝且无已验证发现时形成 `INCONCLUSIVE`；已执行检查中无此类障碍且没有验证发现时形成 `NOT_CONFIRMED`。

`NOT_CONFIRMED` 只适用于本次已执行检查；未调度的检查项仍须展示。取得 flag 也可能使通用任务 `success`，但没有已验证漏洞时报告仍为 `NOT_CONFIRMED`。验收需分别断言两个字段，不把二者合并成一个成功标志。

### REQ-09 审计完整性与范围

系统 MUST 为已有执行事件写入带前序哈希的 SHA-256 链，并提供校验入口。正常追加和接续记录应保持链有效；修改内容、删除中间记录或破坏前序关系必须能够被校验发现。工具开始、结束、拒绝和运行结论等事件用于关联行为与结果，具体事件名称以实现及样本为准。

审计中已配置的敏感字段应按既有递归脱敏机制处理。链校验是内部完整性检查，没有远端时间戳、独立签名和外部锚点，不能证明日志绝未被整体重算，也不能证明响应内容真实。课程交付保留原始链，再用单独摘要解释，不修改原始审计以改善展示。

### REQ-10 人工审批、介入与撤销

在配置了审批回调的运行中，系统 MUST 在执行相应等级动作前等待明确允许；拒绝或审批超时不能执行该动作。控制台提供 `hint`、`pause`、`resume`、`stop` 和撤权等接口，人工提示进入后续模型输入，停止在主循环边界生效，现有状态及已获得证据保留。

系统没有集中账号审批平台，批准者为运行控制台的操作者。停止与撤权限制后续调度，不能承诺已经发出的 HTTP、子进程或线程在同一瞬间终止。验证需覆盖真实回调调用顺序、拒绝时工具调用次数为零、超时失败关闭和提示进入模型输入，人工课堂签署另行处理。

### REQ-11 多层预算与失败反馈

系统 MUST 执行配置中的决策步数、运行时长、控制器检查数、逻辑时间和连续无新增证据停止条件。重复事实、时间戳变化和笔记不能伪装成新知识来绕过停止合同。预算停止时输出当前事实、停止原因和未测项；模型错误与重复动作的反馈应回灌给下一步决策。

当前默认值是 40 步、1800 秒运行预算、40 次控制器检查、900 秒逻辑预算、连续 4 步无新证据停止，工具超时 300 秒。这些是配置参数，不是性能保证。模型单次重试和退避也有实现上限；咨询另受调用次数约束。token 和费用当前用于统计，不能写成已有金额硬闸门。

### REQ-12 状态快照和读者兼容

任务主控 MUST 以完整 JSON 快照保存 `RunState`，供工作台、报告和复核读取。写入采用同目录临时文件后替换，失败时应保留旧完整文件并清理临时残留。状态还原需兼容已有缺省字段、整数化端口键和旧样本中尚不存在的可选字段。

状态包含事实、步骤、假设、结论、覆盖、统计和产物定位。验证分别检查 round-trip 内容、替换失败时旧文件不变，以及工作台可读取。`from_dict` 供读取和重建视图，当前没有从任意快照恢复控制器预算、模型会话和在途请求的全流程能力，因此本规格不把快照读取标成自动断点续跑。

### REQ-13 假设调度与可解释反馈

开启假设台账和调度开关时，系统 MUST 把能够绑定注册检查项的候选假设转为本步方向，优先考虑显式任务要求的漏洞类，并过滤当前控制器记录的已执行检查。没有对应假设但存在任务要求的注册检查时，允许目标驱动派发。描述性、低于门槛或无法绑定的假设不强行计入有效调度。

调度不代替主控发出动作，也不绕过控制器。遵从统计应使用控制器解析后的 `test_id`；双方均有明确 ID 时，同工具的另一检查项不能计作遵从。开关关闭后不能继续向模型注入调度指令。当前匹配仍主要基于漏洞类，覆盖统计与位置绑定的限制见 OQ-01、OQ-04。

### REQ-14 专职咨询的建议边界

启用 `run.specialists` 后，系统 MUST 将 recon、web、review 角色限定为独立上下文的一次咨询。子角色不能执行目标工具、直接修改事实、写入 flag 或再次委派；主控采纳建议后必须发出新的普通工具动作，重新经过执行裁决。review 角色只返回复核摘要。

默认咨询关闭；默认最多 3 次、输出上限 1200 tokens、上下文上限 6000 字符。无效建议及模型失败也消耗次数，防止无限咨询。strict 不会因打开开关而隐式增加咨询注册项。验证包括零隐式执行、越界建议仍被拒、恶意状态字段被清理、跨运行预算隔离和含子响应的录制回放。尚无数据支持咨询必然提升任务成功率。

### REQ-15 分层信息可见性

系统 MUST 在已实现的保护位置执行相应可见性规则：审计按字段名脱敏；报告不直接展示凭据明文；状态摘要只显示凭据主体及服务；专职咨询只接收有界快照，不接收凭据口令和完整历史。API Key 从既有环境变量接口获取，不作为课程证据写入版本库。

这些规则具有明确适用边界。`RunState.to_dict()` 当前会序列化凭据字段，主控原始工具观察也不具备通用内容级秘密检测。因此原始状态、响应及录制均按本地敏感产物处理，只在虚构数据靶场验证，精选提交前检查内容。该要求的测试只证明列明的脱敏位置，统一持久化脱敏和模型输入 DLP 属于 OQ-05。

### REQ-16 报告与只读复核

系统 MUST 从实际状态生成 Markdown 和自包含 HTML 报告，包含任务摘要、发现、证据、复现信息、工具时间线及结论覆盖信息。空状态也应能够渲染；凭据按报告的保护方式展示；HTML 不依赖外部脚本和样式才能阅读。

`trina review` 对状态及审计只读检查，指出缺证据的 verified/exploited 发现、结论矛盾、覆盖缺口及需要补测的注册项。它不能自行执行补测或作为人工签署。验收检查输出文件、章节、证据缺失告警和工具调用边界。报告中的“复现命令”不等于已经由独立角色执行成功。

## 三、评测、工程交付与连续性

### REQ-17 有范围的评测指标

评测 MUST 依据场景声明的 ground truth、漏洞类和评分范围计算指标。已声明范围内未匹配发现可以计为 FP，未提供完整真值的场景不能假定所有其余发现都是误报。别名归一化、flag 条件、端口和服务等成功标准依各场景单独判定。

每份评测解释需指出统计单位、分母、样本数、模型和工具条件。truth 数据用于判分，不进入 Agent 的任务事实提示。确定性机制测试、历史真实模型试验和官方基准成绩分别表述。当前运行内部指标不能替代对真实负例和独立漏洞复现的验证。

### REQ-18 可重复的真实机制验证

仓库 MUST 提供不依赖付费模型的端到端验证入口，固定动作序列但真实调用工具及回环 HTTP 服务。两轮验证分别创建新端口、新靶机和新运行目录，检查 SQLi 发现带证据、假设确认、任务与结论状态、审计链及报告复核结果。输出目录已存在时不得覆盖旧证据。

验收以 `scripts.verify_decision_evidence` 的输出、每轮 `summary.json`、状态和审计为准。固定的是模型决策，运行时间、端口和 run_id 不要求逐字相同。该实验用于排除旧状态及缓存偶然成功，不声称测量模型发现未知漏洞、跨靶场泛化或多角色收益。

### REQ-19 需求到证据的仓库追踪

课程文档 MUST 为每条强制要求提供稳定 ID，并连接场景、责任任务、代码或检查入口以及证据位置。仓库首页提供课程导航，追踪清单使用可机器读取的 JSON。检查脚本核对引用文件、Markdown 链接、要求与任务 ID、场景分类和实际发现的测试名，引用漂移时返回非零退出码。

机械检查验证的是关系存在和基本一致性，不能自动判断自然语言规格是否充分、评测结果是否能推广或教师是否认可。文档修改影响要求时，规格、场景、矩阵和清单需同一变更同步维护。课程正文不得包含伪造的人类评审结论，原始课件不整包上传。

### REQ-20 人工连续性与交接

交接文档 MUST 保存当前状态、最后验证代码版本、开放失败、已有决策、人工问题、下一安全动作和不应重复的操作，并定位到规格、计划和证据。当前版本通过 [continuity.md](continuity.md) 承担工程级交接，运行 `run_id` 继续关联到产品状态和审计。

工程交接不能伪装成产品自动 resume。交接者先校验版本、配置和证据，再决定只读复核或创建新运行；原运行的审批、撤权、预算不能因为复制状态而视为继续有效。验收包含字段和路径检查以及人工按交接说明复现两条命令，后一项保留待人工复核状态。

## 非功能约束与度量口径

| 方面 | 场景、条件与验收口径 | 已知限制 |
|---|---|---|
| 可重复性 | Python ≥3.10、已装项目依赖，回环端口可用；固定决策验证两轮均满足机制断言 | 不保证真实模型采样结果一致，依赖版本目前只有下限 |
| 可靠性 | 快照替换失败后旧 JSON 可解析，异常工具产生错误结果，回归无失败 | 不保证断电持久化或在途操作强取消 |
| 成本 | 文档检查和固定决策验证不调用收费模型；咨询次数及输出量按配置约束 | 模型费用统计没有金额硬上限 |
| 时间 | 每次报告保留实测耗时；超时按对应层配置判定 | 未建立跨机器 P95 延迟基线，不编造毫秒或成功率承诺 |
| 兼容 | CLI 子命令、既有动作 JSON 和旧状态读者保留；本次文档变更不迁移状态结构 | 未来字段删除和语义调整必须另有迁移与回滚方案 |
| 可维护性 | 所有 REQ 都能通过清单找到场景、任务和验证位置，链接检查无悬空引用 | 文本质量和工程取舍仍需人工审查 |

## 规格变更规则

删除要求需保留 ID 的历史和替代关系，不将旧 ID 分配给另一种行为。改变配置默认值、动作协议、字段语义或验收判据时，同步更新影响分析、相关 ADR、场景和清单。未达到的要求记录为条件或缺口，不能通过删断言、降低拒绝规则或改写历史证据取得表面通过。
