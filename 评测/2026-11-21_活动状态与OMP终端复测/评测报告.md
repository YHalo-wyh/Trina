# Trina 活动状态与 OMP 终端复测

日期：2026-11-21
题集：固定终端回放，包含短输出与工具、12 万字符长历史、四路活动输出
执行状态：本人在同一台 Windows 机器上实际执行，两种实现使用同一 Kitty VT 引擎、120×36 终端、相同输入流和三轮交错顺序。

## 变更与判定

本轮检查活动行能否准确显示当前步骤，同时避免拖慢正文与工具输出。

- `tool.requested` 只保存步骤关联，不提前声称工具正在执行。
- `tool.started` 显示 `↳ 第 N 步 · 读取文件`、`运行终端命令` 等小字。
- 对应的 `tool.finished` 清除动作小字并进入结果整理状态。
- 后台终端空闲运行时显示活跃作业数和真实时长。
- 30 列窄终端不能溢出活动行，任务标题仍在右侧可见范围内。

上述事件顺序、窄屏和后台作业状态均有自动测试覆盖。终端性能使用仓库既有 OMP 对照 Harness 重跑。

## 三轮实测

以下为三轮各自 P95 的中位数，单位为毫秒。数值越低越好。

| 场景 | Trina 输出 P95 | OMP 输出 P95 | Trina 按键 P95 | OMP 按键 P95 |
| --- | ---: | ---: | ---: | ---: |
| 短输出与工具 | 19.111 | 33.644 | 14.761 | 14.117 |
| 长历史 | 21.153 | 31.633 | 18.820 | 33.266 |
| 四路活动输出 | 17.621 | 21.146 | 17.693 | 32.486 |

Trina 在三个输出场景均低于本次 OMP 样本。短场景按键两者接近，Trina 慢 0.644 ms。长历史和四路场景的 Trina 按键 P95 更低。

| 场景 | Trina 绘制 P95 | OMP 绘制 P95 | Trina CPU 中位数 | OMP CPU 中位数 | Trina / OMP 内存 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短输出与工具 | 16.743 | 7.945 | 734 | 359 | 43.7 / 147.6 |
| 长历史 | 19.827 | 16.597 | 1094 | 750 | 45.8 / 152.6 |
| 四路活动输出 | 16.113 | 7.786 | 1203 | 594 | 45.3 / 145.0 |

Trina 的可见输出延迟和工作集占优，应用绘制 CPU 仍高于 OMP。长历史翻页 P95 为 Trina 24.838 ms、OMP 0.528 ms。两者路径不同，Trina 使用应用内可选择视口，OMP 使用终端原生历史滚动。当前 Trina 已低于一帧 33.3 ms 的交互预算，但没有在滚动或 CPU 上追平 OMP。

## Rust 取舍

活动行的热路径是进程内事件状态、Unicode 宽度和 prompt_toolkit 差分帧。将它拆成 Rust 子进程会增加序列化和进程通信。现有 Rust 原生层继续用于文件读取、固定字符串搜索等大数据工具。本轮没有为单行 HUD 新建 Rust 边界。
