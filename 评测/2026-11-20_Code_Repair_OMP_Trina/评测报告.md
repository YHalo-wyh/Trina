# OMP 与 Trina 代码修复对比评测

日期：2026-11-20  
题目：本地 `slugify` 代码修复任务  
环境：同一台机器的 Ubuntu-24.04 WSL  
模型：OpenCode Go `deepseek-v4.1-flash`，思考强度 `max`  
判定：`python3 -m unittest -v`，4 个测试全部通过才算完成。

## 题目

`buggy.py` 将连续非字母数字字符替换为单个连字符，但替换后没有裁剪首尾连字符。`README.md` 明确要求小写化、连续替换、首尾裁剪和 ASCII 字母数字保留。`test_buggy.py` 包含 4 个测试，初始状态有 2 个失败。

## 同机结果

| 运行 | 墙钟 | 模型请求 | 工具调用 | 终态 | 测试 |
|---|---:|---:|---:|---|---|
| OMP | 24.727 秒 | 未由文本模式暴露 | 未由文本模式暴露 | 完成 | 4/4 通过 |
| Trina 原始通用路由 | 97.744 秒 | 11 | 13 | `partial / INCONCLUSIVE` | 4/4 通过 |
| Trina 代码路由优化 | 32.854 秒 | 5 | 7 | `success / CONFIRMED` | 4/4 通过 |
| Trina 代码路由 + 预取 | 29.379 秒 | 4 | 5 | `success / CONFIRMED` | 4/4 通过 |

Trina 优化后比原始通用路由减少约 70% 墙钟时间和 64% 模型请求。与本次 OMP 运行相比仍慢约 18.8%，因此不能宣称已经全面超过 OMP。OMP 的文本模式没有提供可核对的请求数和 Token 统计，本表只比较实际墙钟和结果。

## 实施的优化

- 增加英文代码任务路由，识别 `fix`、`test`、`unittest`、`function` 等关键词。
- 代码任务只暴露终端、工作区读写、搜索和必要的 Git 工具，隐藏 Web、漏洞、资产和浏览器能力。
- 没有 `.git` 时自动隐藏 `workspace_git`，提示词同时禁止 `git status`、`git diff` 和父目录扫描。
- 首轮受控批量读取 README、目标源码和测试文件。
- 题面声明 `unittest`、`pytest`、`cargo test` 或 `npm test` 时，在模型决策前运行一次基线测试。
- 代码任务最终状态由真实测试工件确认，测试通过后 verdict 为 `CONFIRMED`。

## 限制

- 这是单个本地代码修复任务，不能代表所有编程任务或 CTF 类型。
- OMP 文本模式没有输出结构化 Token 和工具统计。
- Trina 仍有模型请求延迟，后续需要在多文件修改、失败恢复和多 Worker 编程任务上继续测试。
