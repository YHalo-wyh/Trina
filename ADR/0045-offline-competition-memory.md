# ADR-0045 离线竞赛经验库

状态：提议。日期：2026-11-25。

## 背景

Trina 的 `HypothesisLedger` 记录一次任务中的假设及其结果，`RunState` 保存本题事实和证据，`ConversationContext` 把必要的状态差量传给模型。会话恢复保留这些资料，下一道题需要能按条件检索可复用的结论。

本提议面向离线算法、逻辑和数据分析题。经验库存放经过复核的解法适用条件、反例和验收方法。

## 单题工作流

| 阶段 | 产物 | 转入下一阶段的条件 |
| --- | --- | --- |
| 理解问题 | 目标、附件或数据集、输入规模、运行环境、结果格式和验收规则 | 能说清怎样判断正确结果 |
| 提出假设 | 通常保留 2–3 条最可能的路线及其成立条件 | 每条路线都有可核对的预测 |
| 选择验证动作 | 小样本、边界用例、反例或计算量估算 | 动作能区分候选路线，预期耗时有依据 |
| 动态调整 | 保留、降序或证否的理由，以及本题证据引用 | 新证据已改变路线排序，或已足以排除其余方向 |
| 验证结果 | 判题器回执、本地参考结果或独立校验 | 当前输入和要求均有对应的验收结果 |

优先选择能检验多个候选前提的动作。耗时按端到端记录，包含模型等待、生成样例和执行验证。一次运行未得到新信息时，先核对验证设计与环境。明确反例才用于证否相应假设。有足够证据通过验收后收尾。

## 研发顺序

1. **先固定验收和停止时点。** 每道离线题配一组独立断言，记录第一次通过的时间与验收时的产物版本。验收后继续运行的时间另外统计，便于发现重复检查和收尾拖延。
2. **再减少无效决策轮次。** 候选路线写明预期结果和能证否它的最小样例。优先做能改变路线排序的验证。对同一输入与代码版本重复执行相同检查时，复用已有结果。输入、代码或判断条件变化后可以重验，并记录变化原因。
3. **复用已有后台执行。** 两项本地检查的输入完整、结果彼此独立时，可以重叠执行。依赖上一项结果的工作等待对应结果。记录主任务等待时是否还有可做的独立工作，以及拆分、合并结果实际花了多久。
4. **最后加入跨题经验。** 用本题的输入约束筛选经验卡，明确哪些条件匹配、哪些需要重验。经验卡只影响候选优先级，当前题的独立断言负责验收。

## 跨题记忆

| 字段 | 保存内容 |
| --- | --- |
| 题型与特征 | 离线题型、输入规模、数据分布、版本与约束标签 |
| 路线与状态 | 已验证的解法、被证否的前提，或当前环境阻塞 |
| 适用条件 | 方法成立的输入和环境条件。数据变化时需要复查的条件 |
| 验收方法 | 最小样例、确定性检查方法、预期结果和证据编号 |
| 耗时 | 样本数、实测时长及对应输入规模和环境 |
| 来源 | 原题或夹具标识、版本、核对日期和本地证据引用 |

初版可用独立的 SQLite 文件保存上述字段。先由用户复盘并确认保存。相同题型与条件下的同一结论可合并耗时样本。条件冲突或来源版本变化时保留各自记录，查询时标注需重验的条件。

检索先筛题型与关键约束，再按证据完整性和相关性排序。默认展示少量匹配卡片，每条提供结论、适用条件、最小校验和证据引用。用户可按需展开原始工件。没有可靠匹配时返回空列表。历史会话和完整日志保留在其原始位置。

## 示例

对于「统计和等于 K 的连续子数组」，先查输入是否允许负数。有负数时，输入 `[4, -1]`、`K = 3` 的正确答案为 1。这个反例能证否「和超过 K 时可以立即缩窗」的前提。经验卡保存反例及其适用条件。下一题仍以当前输入约束和独立验收为准。

## 对照评测

同一题分别用基线和单项改动运行。固定题目版本、独立断言、模型、供应商、思考档、最大并发、时限和总 Token 配额。用干净工作区开始，交替运行两个版本并重复配对，减少模型服务拥堵和缓存差异。把主会话和全部子任务的 Token 都计入本题。

| 指标 | 记录口径 |
| --- | --- |
| 通过率 | 时限和总 Token 配额内经独立断言验收的题数除以全部题数。记录每个版本独有的通过与失败 |
| 解题时间 | 从收到题目到首次验收通过。统计全题平均时，未通过的题按评测时限计。验收到退出的时间单独记 |
| 无效调用率 | 重复检查未变化输入、只查到同一状态的轮询、参数错误等无效工具调用次数，除以实际发起的全部工具调用次数。证否假设的检查和产物变更后的重验记为有效 |
| 决策效率 | 首次有效证据耗时、模型轮次、总 Token。记录模型等待、工具执行、工具结果到下次请求之间的时间 |
| 记忆效果 | 适用经验的召回数量、误召回数量、额外上下文 Token。按题型和输入条件查看变化 |

按「验收与收尾」「验证顺序」「后台重叠」「经验检索」逐项做对照，另跑一组全部启用的版本。先比较独立验收通过率，再比较全题耗时与无效调用。配额用于对照评测。固定回放用于检查计数和状态变化，真实模型对照用于衡量决策质量。

经验卡从练习题产生。测试题和同源变体一并留在测试侧。每轮复用同一份经验库快照，防止前一次跑题的结果进入下一轮对照。Token 用量以提供方回执为准，缺失时单独标记。

## 经验库验收

- 同一题型的不同输入条件能检索出各自的经验。有冲突或缺关键约束时提示缺项。
- 检索结果只包含短卡片与证据引用。无匹配时直接返回，并保留原任务的判断流程。
- 保存过的环境错误仍标记为环境错误。结论、反例和阻塞可以独立复查。
- 用固定的离线 Python 题组测试关闭记忆与启用记忆两种条件。出现通过率下降时，逐题回查误召回的经验卡。
