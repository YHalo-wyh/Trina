# ADR-0034：直接样式片段与稳定终端块复用

- 日期：2026-11-16
- 状态：接受

## 问题与依据

上一轮同机同流评测中，Trina 短输出、120K 历史、四路活动块的可见延迟 P95 分别为 130.7、342.8、397.2ms；OMP 为 34.9、34.4、20.7ms。剖析确认两项重复工作：每次增量重新执行 Rich Markdown/Syntax 排版与 ANSI 解析；较早活动块变化时，后续稳定块也重新排版。屏幕帧仍含多余调度等待和空闲刷新。

OMP 发布包 `@oh-my-pi/pi-tui@18.20.2` 的 Markdown 实现包含稳定前缀、token 行缓存与流式高亮。Trina 保留 Python 与 prompt_toolkit，借鉴其稳定内容复用原则，把渲染工作移至实际显示帧。

## 决定

1. CommonMark 块和行内 token 由现有 Rich 依赖链中的 markdown-it-py 解析，`markdown_view.py` 直接生成样式片段。全屏界面消费片段，非全屏输出才生成 ANSI，并按显示单元换行。该设计避免把任意 Markdown 当作手写正则协议。
2. 常规 Python/JSON 单行高亮使用最多 4096 项的 LRU，单行超过 4096 字符时绕过缓存；lexer 与 token 样式也有上限。多行字符串、续行与其他语言使用整块高亮，不保留不断增长的大代码快照缓存。
3. `ResponsiveText` 支持延迟片段入口，工具事件和多路正文只替换当前快照。工具卡片使用线性边框排版，命令以主题色显示，输出保持字面内容；错误与 stderr 独立着色。较早块变动时，`TranscriptControl` 复用后续稳定块的已折物理行。
4. 旧 ANSI 内容继续兼容。常见 SGR 按样式段转换，特殊控制序列退回 prompt_toolkit 原解析器。终端净化、选择复制、宽度变化、历史恢复和事件持久性不受此优化绕过。
5. 显示调度间隔收紧到 1/120 秒且不延后渲染。`full` 保留动画刷新，`none/reduced` 取消空闲周期刷新。支持的终端仅在重叠行相同且几何尺寸未变时使用 SU/SD 搬运行。
6. 主界面挂起时拒绝迟到的读键/flush 回调，嵌套表单继续使用 AppSession 原输入。同步命令线程通过 `run_panel()` 把嵌套面板投递回主 UI 事件循环，避免每次弹窗新建、关闭 Windows 输入执行器。独立启动表单仍使用普通运行入口。弹窗测试等待首帧再提交回车，并断言面板复用主循环；另有主界面挂起不消费输入的确定性断言。

## 兼容性与取舍

不新增网络调用或模型参数，不改 AgentRuntime、Worker 租约、授权、审计、SQLite FULL 同步和消息恢复协议。Markdown 表格使用紧凑分隔行，代码取消 Rich 的整块背景填充，工具输入使用主题色；它们的显示样式与旧版存在差异，文本与状态必须可核查。语法高亮不是执行判断，工具退出状态仍来自真实事件。

CommonMark token 解析仍针对当前消息；多行语法和非常长的活动块可能增加工作量。跨平台字体和 emoji 的显示宽度由终端决定。1/120 秒是调度间隔，不是帧率保证。终端滚动区属于有条件优化，首次绘制、几何变化或不支持的输出继续使用普通差分。

## 验证

`tests/test_markdown_view.py` 覆盖内容、控制字符净化、嵌套强调、引用链接、表格、围栏、多行字符串、代码行缓存与非全屏 Unicode 换行；`tests/test_transcript.py` 检查稳定块不重排、宽度失效、ANSI 兼容、滚动与选择；流式事件、弹窗、Worker 面板继续执行原回归。

性能证据保存在[同机同流优化评测](../评测/20261115-omp-output-benchmark/optimization/README.md)。原始旧基线保留，优化结果独立保存；相同输入、终端与模型外 UI 组件各运行三轮，第二轮交换顺序。UI 回放只能支持输出链路结论，不能用于推断模型首字、网络、工具执行或完整 Agent 解题吞吐量。CPU、滚动、可见覆盖率与绘制耗时必须单列，不以一个延迟指标代替整体性能。
