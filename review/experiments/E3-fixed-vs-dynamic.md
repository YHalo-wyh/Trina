# 实验卡 E3 · 固定全跑 vs 动态选择检查项（A/B，含七项报告）

- **Claim**：在**相同声明目标**下，动态选择注册检查项（现状）与固定全跑相比，
  覆盖、检出、误确认、未确定、工具故障、越界动作、成本七项各自如何变化。
- **状态**：**部分完成**——只有"动态"臂的真实数据；"固定全跑"臂尚未执行（下表 `—` 处为缺口）。
  按课程口径：**覆盖目标不同的比较只能讨论"不同服务档位的取舍"，不能宣称提效**。
- **固定条件**：靶机 = 内置模拟器（lab，HTTP 9099 + SSH 2222）；模型 = `deepseek/deepseek-v4-flash`；
  动作上限 `verify`；注册检查项 = `configs/ranges/lab.yaml` 的 11 项
- **唯一主要自变量（计划）**：调度方式（阶段机+目标要求 [动态] vs 固定顺序全跑 [固定]）
- **无法控制的变量**：模型采样（同一提示词可能给出不同路径）→ 每臂需多次重复才能下结论

## 结论边界（能说什么 / 不能说什么）
- ✅ 可以说：当前"阶段机 + 目标要求 + 注册检查项"能在预算内给出**可解释的覆盖**（已测/未测/原因齐全），
  并且越界请求在执行层被阻断（记录为 `boundary_events`，非实际越界）。
- ✅ 可以说：本轮 8 个 Web 场景的 precision 100%、FPR 0%、GT 命中 88.9%——**这是动态臂的成绩**。
- ❌ 不能说：动态优于固定——固定臂未跑，且两臂任务不完全相同。
- ❌ 不能说：成本更低——缺少"固定全跑"的耗时/步数对照。

## 下一步（把实验做完整）
1. 增加一个"固定全跑"模式（按注册顺序执行 11 项，不做阶段跳跃），在**同一任务**下跑多次（建议 3 次）；；
2. 两臂都记录七项指标（含每项检查的耗时与模型调用数），再谈取舍；
3. 若固定流程在相同预算内覆盖更全、成本更低 → 按课程口径应把它作为推荐 Baseline（写入 `ADR-0012` 的修订）。

## 决策
见 [ADR-0012](../../design/adr/0012-fixed-vs-dynamic-checks.md)（当前结论：**保留固定骨架**，动态只发生在阶段内；本实验用于后续修订）。
