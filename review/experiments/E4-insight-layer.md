# 实验卡 E4 · 洞察层（假设台账 + 失败分类/循环守卫 + 证据图）值不值这个成本？

- **Claim**：
  (a) 机制上——每步动作能追到它要验证的假设，且假设状态由**工具结果**确定性推进（不采信模型自我宣告）；
  (b) 成本上——把洞察层回灌给模型要花多少 token/时间；
  (c) 效果上——(a) 是否带来更多**已验证**结论。
- **状态**：**完成第一轮**（两臂各 3 次，同一任务、交替执行）；机制与成本已实测，**效果只有方向性数据，不能宣称提效**（n=3 + 模型采样）。
- **固定条件**：靶机 = 内置模拟器（lab，HTTP 9099，仅回环，每次 `play` 自拉自收）；模型 = `deepseek/deepseek-v4-flash`；
  动作上限 `verify`；`max-steps=8`；任务 `--goal "拿到 flag"`
- **唯一主要自变量**：`run.hypothesis_ledger` / `run.loop_guard`（洞察层开关）。
  关掉只影响**模型看到什么**（提示词里没有假设台账、循环/失败建议不回灌），
  `redundant_action_rate` 与 `fail_*` **照常统计**——两条臂的度量口径一致才可比。
- **无法控制的变量**：模型采样（同一提示词路径不同，单次差异可达 2 倍成本）；靶机时序；当日 API 抖动。
  因此**每臂 3 次只能看方向**，不能做显著性判断。

## 实验二（负对照，意外获得）：靶机不在场

第一次跑 A/B 时，靶机在我启动后被环境回收（`play` 只在不给 `--target` 时才自拉靶机，
那 6 次拿死靶机跑），两臂数据无效——但它本身是有意义的**负对照**：
原始数据 `data/E4-negative-control-lab-down-20261016.json`（两臂各 3 次）

| 汇总 | 开 | 关 |
|---|---:|---:|
| 成功 / flag / 发现 | 0 / 0 / 0 | 0 / 0 / 0 |
| 执行检查项（均值） | 2.0 | 2.0 |
| 失败计数（合计） | 9 | 9 |
| 结论状态 | 全为 **INCONCLUSIVE** | 全为 **INCONCLUSIVE** |
| 假设登记（均值） | 5.33 | 0 |

结论：环境坏了的时候，洞察层**不会无中生有**（不会把"连不上"说成"没漏洞"），
两臂都把失败归因为环境类并给出 INCONCLUSIVE；差异只在"有没有把假设写进台账"。

## 结论边界（能说什么 / 不能说什么）
- ✅ **可以说**：开关真的生效且可审计——开臂每轮登记 3–5 条假设（均值 4.33），关臂恒为 0；
  假设内容现在进**审计哈希链**（`react.action.hypothesis`），不只是可改的 `state.json`。
- ✅ **可以说**：洞察层不是免费的——同任务下 token 均值 +44%（9807 vs 6801）、Time to Evidence +3.8s、
  步数 +6%；成本约 2 倍（受缓存命中影响，token 增幅更可解释）。
- ✅ **可以说**：本轮 3 次里"已验证发现"开臂 4 个、关臂 1 个（2/3 次运行给出 CONFIRMED vs 1/3）——
  方向与设计意图一致（先立假设再验证），但这是 n=3 的方向性观察。
- ❌ **不能说**：洞察层提高成功率（两臂都 3/3 拿到 flag）；降低冗余（本任务两臂冗余率都是 0，
  **循环守卫一次都没触发**，守卫的收益根本没被这个任务测到）。
- ❌ **不能说**：成本可控——+44% token 是既成事实，是否值得要看"多 1 个已验证结论"在目标场景里值多少钱。
- ⚠️ **样本量**：每臂 3 次、单靶机、单任务、单模型；模型采样导致单次成本差异可达 2 倍（见开臂首轮）。

## 下一步（把实验做完整）
1. **换硬任务**：用需要多步假设推演的场景（Pikachu/DVWA 多漏洞、或对抗代理下的软 404/假 flag），
   让"猜错方向→换路"真正发生，再比 `redundant_action_rate` 与 `recovery_rate`；
2. **加样本**：每臂 ≥10 次，报告均值 + 极差/中位数，避免被离群点带跑（本轮已出现 2 倍成本差异）；
3. **成本口径**：把"每拿到 1 个已验证发现的 token 成本"作为主指标（当前：开 ≈ 7355 token/个，关 ≈ 20404 token/个），
   而不是总 token；
4. **守卫臂单独测**：注入"同一动作重复失败"的场景（如靶机半死），验证阶梯建议是否真的把策略换掉；
5. 若硬任务下开臂的"每验证发现在成本"更低 → 默认开启（现状）；反之在预算紧的场景提供 `loop_guard=false` 的低成本档。
