## 原因与修改

逐 SSE 分片的持久写入、订阅回读和累计正文写入会阻塞接收线程；工具增量还会立即运行 Rich 面板/高亮。思考字段没有进入原终端投影，正文里的代码围栏和字典会触发通用协议截断，造成等待到结束的观感。

现在按约 30Hz 合并同类增量：首块立即显示，暂停尾部定时刷新，类型变化、4096 字符阈值、结束和异常强制刷新。FULL 同步和提交后投递保持；连续本地事件直接投递，缺口与失败仍从持久事件重放。思考、正文、工具各自原位更新，工具排版放到显示帧，Worker 四格同样接收流。没有返回推理字段时不编造思考内容。

## 本地链路测量

相同输入为 300 个连续的 `thinking_delta`，每个文本为「思考」，接入真实 EventBus 和 EventTranscript；不包含网络或模型生成。

| 版本 | 持久事件数 | 单次实际耗时 | 内容 |
| --- | --- | --- | --- |
| 修改前 | 302 | 11.193 秒 | 原实现每分片提交 |
| 最终补测树 | 4 | 0.384 秒 | 拼接后严格等于原 600 字符，`text_exact=true` |

修改前数字来自本轮修改前执行的诊断命令记录，未事后模拟。当前原始测量结果见 [measure.json](measure.json)。可重跑入口：

```powershell
python -X utf8 -c "import runpy; runpy.run_path('evidence/20261115-stream-output/measure.py', run_name='__main__')"
```

这只是本机单次链路测量。磁盘、终端负载和 import 冷启动会影响结果；不能据此承诺真实模型每秒 Token 或端到端解题提速比例。

## 兼容性与边界

- 保留标准 API 消息和工具调用、实际授权/超时、持久恢复、游标、失败重试、输入草稿和历史选择。
- 事件分片边界可改变；拼接文本、阶段顺序和终态必须一致。合并频率不是慢磁盘/终端上的硬帧率保证。
- JSON/DSML 动作协议继续过滤。供应商的推理字段独立显示，不进入正式回答或事实图。
- 非 TTY 保留完成记录；增强终端才提供相同块的实时原位刷新。供应商首字延迟、模型推理时长及网络耗时仍存在。
