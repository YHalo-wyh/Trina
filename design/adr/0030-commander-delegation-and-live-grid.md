# ADR-0030：Commander 实际委派与四格观察

- 日期：2026-11-14
- 状态：已实施
- 关联：TR-03、TR-17

## 调研与问题

用户希望继续对照 OMP 的子任务能力，去除底部操作教学行和加粗 Commander，并同时查看多个 Worker。前版只有子任务管理页，模型仍缺少直接委派入口。

对照 [OMP 子 Agent 提示词](https://github.com/can1357/oh-my-pi/blob/main/packages/coding-agent/src/prompts/system/subagent-system-prompt.md)、[任务设置](https://github.com/can1357/oh-my-pi/blob/main/packages/coding-agent/src/task/settings.ts) 和 `task/executor.ts` 相关入口，选取可落到现有架构的能力：异步分工、结果回收、定向补充与取消、按任务配置模型。四宫格是 Trina 的展示方案，不是声称 OMP 使用相同界面。

| 能力 | Trina 本轮行为 | 边界 |
|---|---|---|
| Agent 委派 | 注册 `worker_tasks`，在控制台聊天及 `/run`/`/play` 注入宿主 | 非控制台独立入口不自动创建宿主；子 Worker 不递归分工 |
| 异步结果 | spawn 仅表示接受，list/result/wait 查真实状态与证据 | 最多短等 10 秒；结束结果缓存最近 128 项，完整产物在运行目录 |
| 消息/取消 | Commander 串行处理，走原有 steer 与停止接口 | 正在进行的网络调用受传输超时约束，不承诺瞬时停止 |
| 多任务观察 | 四格/列表切换、聚焦、分页、历史浏览 | 小屏显示所选任务；没有接管 Worker 的完整聊天会话 |
| 上下文 | 主 Agent 有界读取结果，子事实不自动合并；动态末尾只放任务元信息 | 不同步完整对话，不把不同题目的结论自动判为当前事实 |

## 决策理由

系统提示词明确把可独立验证的分支委派，说明文件范围、依赖和验收，主 Agent 继续关键路径。通过真实注册工具落实，避免只写一句“可以调用 Worker”却无执行接口。权限仍由 ToolRegistry 与实际子任务执行链裁决。

单项停止与整场停止组成原有 Event 接口；追加消息进已有 steer 队列，不创建另一种模型消息模板。图状态仍由 Commander 唯一写入，取消不能记为成功。

四格从已解析的 assistant、动作与工具事件投影。原始 model 文本可能是 JSON/DSML，不能直接显示为答复；隐藏思考增量也不转为正式对话。每任务块与物理行有界，按版本/宽度缓存，稳定任务不因另一任务刷新而重排。

长输出压力检查中，整任务重排约 320K 字符需约 106 ms；改为按块缓存后，更新单个 4000 字块约 1.7 ms。本地数字只说明排版成本，不代表实际终端帧率。另在独立快照回归中发现：把不可用委派工具放入 CTFY 紧张窗口会导致请求在发送前耗尽预算。因此没有宿主时，合同和原生 schema 都省略该工具；注册与执行边界仍然存在。

## 验证

`tests/test_worker_dashboard.py` 覆盖主 Agent 实际工具委派、真实 Python 子进程、结果读取、历史显示恢复而不重跑/重计费，单项消息和取消不干扰兄弟任务，四格分页/窄屏/放大/缓存，以及去除提示和普通字重。`evidence/20261114-worker-dashboard/` 保存验证与真实屏幕缓冲预览；截图使用标注的演示内容，不能作为线上模型成绩。
