# ADR-0018：事实摘要维护上下文，实时覆盖参与调度，状态原子替换

- 日期：2026-10-21
- 状态：已实现
- 关联：[ADR-0016](0016-deterministic-hypothesis-scheduling.md)、[ADR-0017](0017-specialist-consultation-without-blackboard.md)

## 发现的问题

1. 任务调度器原来从 `state.coverage` 读取已执行检查，但覆盖快照直到收尾才完整更新，
   导致下一轮可能继续派发已经批准运行过的检查。
2. 目标驱动调度先按漏洞类取第一个注册项，再检查其是否执行过；同类第一个检查跑过后，
   其余未测项没有机会成为候选。
3. 对话提示原来只拼接最近 12 条消息，工具动作自身未加入历史，已有事实也未稳定回灌。
   用户要求和动作原因可能滑出窗口，只剩若干孤立的工具结果。
4. 对话模式的失败分类与循环建议只写入 logger，模型收不到建议，无法据此修正下一步。
5. `state.json` 直接覆盖写入，`watch` 或另一个终端可能读取到半个 JSON 文件。
6. 遵从统计把同工具但不同 `test_id` 也判成执行了指定检查；guided 模式反查出的 ID 未送到审批界面。

## 决定及理由

| 问题 | 选用方案 | 为何不选另一种 |
|---|---|---|
| 覆盖过期 | 调度直接读取控制器当前 `executed`，工具结束后刷新状态中的覆盖快照 | 单纯增加落盘频率不会修复内存里读错来源的问题 |
| 同类检查遗漏 | 按漏洞类归组前先排除已经执行的注册项 | 只跳过第一个候选会让其余同类候选继续不可见 |
| 长对话丢进展 | 本轮请求 + RunState 确定性事实摘要 + 有界近期历史；历史保存动作与对应观察 | 暂不让额外 LLM 总结历史，以免增加成本、把推断压缩成事实 |
| 建议未送达 | 将失败与循环反馈追加到实际观察结果 | 日志是给操作者看的，不能假设模型能读控制台 |
| 半文件读取 | 同目录临时文件写完关闭后，再用原子替换更新 `state.json` | 不加“读取失败就当空状态”的兜底，避免把写入竞态掩盖成没有进展 |
| 遵从率失真 | 有明确检查 ID 时按 ID 匹配；审批与调度使用控制器解析出的 ID | 同工具可能检查不同接口，不能只凭工具名算完成指定调度 |

状态摘要只携带工具已经登记的事实；它本身不产生证据，也不恢复完整历史。
本轮用户请求最多 4000 字符，事实摘要约 3000 字符，近期历史最多 12000 字符。
这限制的是对话用户提示部分，系统工具表、假设台账与注册清单仍另计，不能称为整个提示词的硬 token 上限。

原子替换失败时保留旧文件、记录保存错误并清理临时文件。
这保证读者不会看到该实现产生的半份快照，不等同于断电持久性、完整断点续跑或跨进程事务。
Windows 读者占用文件、磁盘满或目录权限异常仍可能阻止替换，旧快照会因此过期。

## 验证

- 两条相同漏洞类检查，第一条执行后，第二轮必须派发第二条，不能重复第一条或丢掉后续候选。
- 对话历史滚动后仍包含已经登记的端口和当前要求；工具动作和观察保持成对记录。
- 模型下一次输入实际包含环境失败的改进提示，而不仅是 logger 中出现。
- 替换失败时已有 `state.json` 不变，临时文件清理；正常 ReAct 回放仍能产出状态文件。
- 已有护栏、审计与证据测试继续作为回归约束，不为通过测试改变授权范围。

## 保留的局限

控制器现有 `executed` 在批准阶段登记，尚未完整区分“批准、工具实际开始、完成、有证据”。
本次修的是调度读取旧来源与候选遗漏，未把批准记录重新包装成完整覆盖证明。
覆盖统计更细的生命周期需要单独迁移控制器契约和现有评测，不能靠修改报告措辞完成。

对话模式仍是有界工具循环，不等同于任务模式的完整 PTES 阶段机。
本次因此同步修正对话提示里“已确定性调度”的不实描述。
