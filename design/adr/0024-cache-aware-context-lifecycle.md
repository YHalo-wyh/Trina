# ADR-0024：增量状态、缓存策略与上下文继承检查点

日期：2026-11-12

状态：Accepted

## 背景

ADR-0022 固定了 system 和初始合同，后续结构化消息仅追加。ADR-0023 在尾部提供真实运行状态。原实现仍逐轮复制完整事实和台账，长期聊天不断增长；缓存统计无法区分可见前缀变化和正常新增内容，后端也没有供应商缓存参数适配。

缓存命中率不足以单独评价运行时。未命中既可能来自新内容，也可能来自前缀、工具、模型、路由或保留期限变化。已有的 77% 观察没有逐请求材料，无法据此分解剩余部分。

## 决定与原因

以 `ConversationContext` 管理当前任务的差量基线、继承检查点及请求诊断，复用 RunState、现有审计和工作目录。事实按结构化条目更新，周期完整快照提供校验基线。时长、计数及后台作业继续通过独立状态栏提供，不混进事实差量。

以 `CachePolicy` 在后端边界适配供应商参数，内部消息保持角色与内容结构。官方域名按已核对能力选择参数，未知中转显式声明后用业务请求协商，不增加独立预热请求。连接拒绝扩展时仅在生成开始前进行一次受控降级。

上下文按预算触发确定性继承检查点，保留稳定指令、全部用户约束、事实、证据引用及最近工具链。完整原件原子落盘后才能替换活动尾部。压缩建立新的 epoch，作为 ADR-0022“持续追加”的明确生命周期边界；epoch 内仍严格追加，首条 system 和初始合同始终保留。

压缩目标低于触发线，减少反复重建；保留信息无法容纳时明确停止。归档失败不得先删除消息。不能用压缩后的低缓存比例推断整体变差，需要同时比较输入量、延迟、真实缓存读写和费用。

## 取舍

未引入额外模型摘要、向量库、缓存服务或插件框架。确定性继承便于复核，代价是旧正文依赖归档查阅，所有用户约束及事实过大时无法继续压缩。Token 估算保守但非精确 tokenizer，实际模型窗口仍需按供应商配置。

Core 与工具快照可提供公共前缀标识，Worker 的对话和事实继续隔离。不承诺不同工具集必然共享 KV，不扩大当前 Worker 的工具集合。`prompt_layers` 保留原默认值，结构对照测试不能代替真实模型质量与费用评测。

## 验证与限制

`tests/test_cache_runtime.py` 覆盖真实聊天/任务执行链、归档失败、约束保护、工具调用配对、前缀分类、供应商原生参数、实际回环 HTTP 能力拒绝及连接切换。没有进行付费供应商实测，不能公布新的命中率或节省百分比。

配置、指标解释和官方资料见 [缓存感知运行时](../../docs/CACHE_RUNTIME.md)。任务级恢复仍沿用 Swarm 既有实现，当前未提供任意聊天 epoch 的一键续跑或后台进程恢复。

实际回放计数、归档压力实验及完整回归输出见 [2026-11-12 缓存运行时验证](../../evidence/20261112-cache-runtime/README.md)。
