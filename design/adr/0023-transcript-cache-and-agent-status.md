# ADR-0023：缓存会话视口、文本选区与末尾运行状态

日期：2026-11-12

状态：Accepted

## 触发问题

流式回复每次增量都将整段 transcript 缓存置空，随后重新渲染全部历史卡片；光标定位又逐帧拆分全部 fragments。历史越长，滚动和流更新越慢。全屏鼠标接管截获了终端拖选，却没有提供应用选区，导致文本无法直接复制。

原上下文包含事实与预算，但这些字段分散在每轮提示中。后台程序缺少独立作业表，模型无法在后续决策时直接判断程序是否仍在运行或已经失败。

## 决定及理由

`TranscriptControl` 按块缓存已排版 ANSI 行，通过 UIContent 按需返回行，滚动只更新位置；只有内容变化和宽度变化触发相应重排。流式增量先替换待绘制文本，按实际帧合并后渲染。该结构参考 Oh My Pi 将稳定历史与可变显示区分开的做法，继续使用本项目已有的 prompt_toolkit。

应用接管鼠标时实现拖选、高亮和复制；F2 可释放鼠标，供终端原生选择。Windows 使用有效隐藏窗口作为 Clipboard owner，写入 Unicode 文本；其他终端使用 OSC 52。输入草稿与会话选区分别保存。系统剪贴板不可用或终端拒绝协议时，应用内部剪贴板仍保留内容，不能直接断言系统复制成功。

`runtime_status.py` 独立生成运行快照，追加在决策请求最后一条 user 消息末尾。system 和此前消息保持不变。快照包含任务进度、阶段、计数、环境观察及后台作业，不替代工具事实，不向其他题目共享作业，也不在正式答复下面输出重复统计。

后台程序通过三个注册工具和既有 `run_external` 启动。每个任务独立持有作业表，记录真实状态及退出码；监视线程只更新作业，漏洞证据仍由工具执行链吸收。作业具有并发、时长、输出及记录上限，默认只继承最小环境。POSIX 进程组和 Windows Job Object 负责任务结束后的进程树回收。

## 限制

窗口宽度变化仍需对全部保留内容重新排版。内部滚动微基准只能证明计算路径变化，不能直接代表全部终端模拟器的鼠标延迟。跨终端剪贴板行为取决于终端支持与系统剪贴板状态。

动态状态在下一次模型请求时提供，不能修改已发送给模型的在途请求。当前后台工具用于持久 Agent 会话；单次 `trina tool terminal_*` 不持有作业生命周期，明确拒绝。后台作业没有跨重启恢复，也没有自动生成新漏洞事实。进程树回收不提供文件系统或网络沙箱。

## 验证

- `tests/test_transcript.py`：稳定历史不重排、增量合帧、Unicode 拖选、真实 SGR 鼠标事件、草稿保留、原生鼠标模式和两种剪贴板通道。
- `tests/test_runtime_status.py`：真实程序的运行、退出码、失败、超时、取消、子进程回收、会话隔离、最小环境、状态栏末尾位置和快照兼容。
- 当前机器规则：TR-03-R04、TR-04-R04、TR-05-R02。
