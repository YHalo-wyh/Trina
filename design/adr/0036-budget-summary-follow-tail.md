# ADR-0036：动作预算后无工具收尾与显式视口尾随

- 日期：2026-11-16
- 状态：Accepted

## 背景

Chat 的工具动作预算与模型决策循环共用上限。模型在最后一次工具观察之后准备交付报告时，循环可能已经达到上限，旧实现直接返回“回复继续”的固定文本。真实观察仍在标准消息历史中，但用户没有得到结论，表现为输出被吞。

内容视口原先用 `_scrollback` 和选区锚点共同推断是否正在阅读历史。一次已完成的鼠标复制仍会留下锚点，后续新增行因此增加 scrollback，底部不再自动出现。

## 决策

1. 普通 Chat 用尽工具动作预算且没有答案时，追加一次标准 `user` 运行数据，明确要求只总结已取得结果。该请求不传 tools，不计入工具动作预算，不执行模型意外返回的调用。
2. 收尾回复继续进入标准消息、显示历史、审计、流事件和用量账本。请求失败时明确显示失败及可继续操作，不伪造结论。
3. CTFY 等把模型调用次数作为平台硬预算的入口不增加展示性请求。
4. 视口维护显式 `follow_latest`。默认开启；主动向上滚动关闭，回到底部、`Ctrl+End`、清空会话或提交输入开启。拖选期间临时暂停，若仍在底部则释放后恢复。
5. 主动历史锁定继续保留稳定可见锚点，新输出不得强行跳回底部。

## 结果

最终报告不再被动作上限替换；正常运行时最新流式内容始终可见，阅读历史时又不会被输出抢走。新增模型调用只发生在确实耗尽动作且没有答案的普通 Chat 回合，因此不会影响提前完成的路径。
