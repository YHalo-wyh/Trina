# ADR-0033：按帧合并的思考、正文和工具输出

- 日期：2026-11-15
- 状态：接受

## 原因

用户观察到输出慢。检查确认每个 SSE 增量均同步写 SQLite、逐个回读订阅，并可能再写一条累计正文；工具增量还会在生产线程立即执行 Rich 面板和高亮。显示层忽略模型思考字段，正文的通用 `{`、`<` 和代码围栏截断规则也会把普通代码缓存到结束。本地 300 个连续思考增量耗时 11.193 秒、产生 302 个事件，说明延迟存在于输出链路自身。

## 决定

参考 OMP 的 `packages/tui/src/chat/assistant-message.ts`、`tool-execution.ts` 和 `frame-rate.ts`：稳定内容复用，只更新活动块，显示刷新集中调度。保留 Trina 既有终端框架。

1. `ModelEventStream` 合并同类增量，首块立即提交，后续约 30Hz；定时刷新空闲尾部，类型变化、4096 字符阈值、结束及异常强制刷新。完整响应和用量仍按原协议处理。
2. EventBus 在事务提交后向连续同进程订阅者直接投递独立快照；缺口、失败与历史恢复继续回读 SQLite。保留 FULL 同步和命名消费者 ack，不引入第二份权威事件状态。
3. 思考字段使用独立低亮度块；正文和工具调用保持各自原位更新。工具卡片的排版延迟到真实显示帧。子 Worker 接收同样的推理/正文事件，但不把 JSON/DSML 作为回复。
4. 文本过滤只等待可能的动作协议前缀，普通代码围栏与代码内字典可继续输出；模型最终消息不得重复追加已显示正文。用户草稿、选择、滚动和恢复继续沿用现有机制。

## 验证与限制

`tests/test_stream_latency.py` 验证字节和阶段顺序、首块、暂停尾部、异常结束、真实本地 SSE 在 DONE 前可见，以及工具按帧排版；`tests/test_events.py` 保留并发、失败续流、持久恢复和去重回归；Worker 面板有分离显示测试。

该改动减少 Trina 的输出处理成本，不会消除供应商首字延迟、模型推理或网络时间。约 30Hz 是合并目标，不是慢磁盘/终端上的硬帧率保证。事件重放的分片边界可以变化，拼接内容和终态必须一致。供应商不返回推理字段时只展示真实活动状态。非 TTY 仍输出完整记录，不能保证与增强终端相同的原位刷新体验。
