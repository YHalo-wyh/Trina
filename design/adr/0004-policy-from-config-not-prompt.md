# ADR-0004：授权判据来自配置与注册表，不来自提示词

- 状态：已采纳（M0/M3）

## 背景
提示词驱动的系统里，最容易被绕过的就是"边界"：只要把范围描述写进提示词，模型就可能被工具输出、
被目标页面文字、或被自己的推理说服而"临时放宽"。课程 P3 也明确：模型不能自行批准扩大范围。

## 决定
- 范围/等级/预算/注册项全部来自 `configs/trina.yaml` 与 `configs/ranges/*.yaml`（人可读、可审查、可 diff）。
- 提示词里的范围描述由 `TrinaConfig.scope_prompt_block()` 生成，**与真实判据同源**，避免"说的和做的"漂移。
- 硬禁止清单（DoS/删库/写 webshell/`--os-shell`/`--file-write`/执行远端脚本等）写在代码里，
  **任何配置都无法开启**。
- 拒绝时返回"原因 + 合规替代做法"，模型据此改走合规路径（`next_hints` / `Tool.level_hint()`）。

## 后果
- 正面：边界可审计（改配置=改边界，且进 git diff）；越界请求在执行层被阻断并留痕（`boundary_events`）。
- 负面：模型需要更多步来"找到合规路径"（用提示词里的替代建议与阶段指引缓解）。
- 已验证：`guard check 8.8.8.8` 拒绝；`sqlmap --os-shell` 拒绝；模型中途换目标被逐动作拦下。

## 被否决的方案
在系统提示词里写"不要扫描未授权目标"并寄希望于模型遵守：属于"把安全寄托在模型的善意上"，
无法通过任何对抗测试。
