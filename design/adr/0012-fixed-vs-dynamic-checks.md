# ADR-0012：固定检查 vs 动态选择——保留阶段机与注册检查项，不做无约束自主

- 状态：已采纳（对齐课程 P3「固定流程可以胜出」）
- 相关：ADR-0006、ADR-0007

## 背景
P3 明确指出：**不按工具数量、自治程度或 Agent 名字评分**；固定流程在相同预算内更便宜且充分时，
应成为推荐 Baseline；动态调度只有在**质量或成本上可证明更优**才值得保留。

## 实验观察（本仓库）
| 形态 | 表现 | 证据 |
|---|---|---|
| 完全动态（早期版本） | 会走捷径（拿到 flag 就收工）、会重复无效动作、覆盖不可解释 | `docs/EVAL.md §4.1` 修前：web 套件 GT 命中 0/N |
| 阶段机 + 目标要求（现状） | 侦察→枚举→验证→取证有顺序约束；任务要求未满足不收敛 | 修后：8 场景中 7 通过，GT 命中 88.9% |
| 注册检查项 + 预算（现状） | 覆盖可统计（已测/未测/原因）；越界请求在执行层被拒 | `trina play` 实测：已测 5/未测 6，CONFIRMED |

## 决定
1. **保留固定骨架**：PTES 阶段机（recon→enum→vuln→exploit→post→report）作为默认流程，
   每阶段有步数预算与目标达成判据（事实驱动）；
2. **动态只发生在阶段内部**：模型在注册检查项里选择"下一项检查"，不决定阶段跳跃与结束条件；
3. **报告七项并存**（P3 稿036 口径）：覆盖、检出、误确认、未确定、工具故障、越界动作、成本——
   不允许只报其中好看的一两项；
4. **证明动态更优的成本门槛**：需在**相同声明目标**下获得同等可信结论，否则只能算"更小服务档位"。

## 后果
- 正面：可复现、可解释、可交接；"没测"和"没问题"被明确区分（三类结论）。
- 负面：不如"自由探索"看起来聪明；对非常规靶场可能需要新增注册检查项。
- 已知边界：主机类场景仍受模型扫描策略影响（波动 2/3 ↔ 1/3），
  下一步是把"目标点名端口"升级为计划层的自动补扫，而不是放宽约束。

## 被否决的方案
"完全自主、不设阶段与预算"：评测中不可复现，也无法回答"到底测了哪些、哪些没测"。
