# ADR-0025：按项目保存历史聊天并通过 /resume 切换

日期：2026-11-13

状态：Accepted

## 背景与前置检查

现有 `/history` 只查看当前进程内的 ChatAgent，`/new` 丢弃活动实例；审计中的 `chat.answer` 只含长度，不能还原完整回复。上下文压缩归档只在触发压缩时创建，也不等于每轮都保存过聊天。原 `/resume` 被用作解除暂停，与操作者期望的历史会话选择冲突。

本次先核对 `ChatAgent` 的标准消息、显示历史、ConversationContext、台账、LLMUsage、控制器和 AuditLog 的生命周期，再确定保存范围。继续使用现有方角选择框和持久终端，不增加独立的会话管理框架。

## 决定与原因

`/resume` 统一表示查看、搜索和切换当前项目的历史聊天，解除暂停使用 `/unpause`。增强终端按标题或 ID 搜索；普通终端提供编号、ID、唯一前缀及最近会话入口。运行中只能列出，避免更换仍在使用的状态和事件对象。

新增单一 `ChatStore`，在配置工作区保存 SQLite。元数据与完整快照在一个事务中更新，列表仅查询 ID、标题、时间和轮次，不加载所有历史。项目以规范化工作目录标识，不能因共享用户运行目录混入其他项目。选择 SQLite 而不是每轮重扫大量 JSON，是为了同时保留原子更新和轻量列表；它不能替代运行证据的审计与报告。

保存显示历史与活动 API 消息两份数据：前者便于阅读，后者保留结构化角色和压缩后的执行上下文。还保存事实、台账、上下文基线及 epoch、用户约束、用量缺失计数和已用预算。用户输入后、工具前后、轮次结束、手动压缩与关闭均保存；保存不额外调用模型。数据库不复制供应商配置或 Key，用户主动输入的正文仍按原文保存。

恢复先取得系统独占文件锁，再载入最新快照，避免读到另一实例关闭前的旧数据。已有审计续写前验证哈希链。先验证并构造目标会话，再关闭当前会话；格式、审计或占用错误不能使当前会话先丢失。新对话 ID 增加随机后缀，避免同秒启动覆盖工作目录。

恢复保留已用预算和撤权状态，但执行控制器及护栏取当前配置，模型连接取当前 `/model` 选择。旧进程不恢复、旧动作不重放；中断会话追加说明，等待下一条显式输入。事实恢复不是对其真实性的独立证明，哈希链也不是外部可信签名。

## 未采用的方案与限制

- 不从旧审计猜测完整回复，也不让模型生成“历史”。旧版本没有保存过的聊天无法补齐。
- 不把全文压成 `USER:` / `ASSISTANT:` 字符串；保存原标准消息及上下文生命周期。
- 不把 `/resume` 同时解释为解除暂停，避免同一入口依赖状态产生不同含义。
- 不恢复后台操作系统进程，也不自动重试可能已经产生副作用的工具。异常退出时，最后一个工具可能已执行而尚未保存观察，需要查审计并重新核对。
- 不提供任意压缩 epoch 导入、项目迁移、聊天删除或旧格式数据库迁移。移动项目目录会改变项目标识；内容视口继续使用有界显示缓冲，完整历史在数据库保留。
- 文件锁防止正常实例并发写同一对话，不提供数据库加密、操作系统沙箱或恶意本地进程隔离。

## 验证

`tests/test_chat_resume.py` 通过真实 ChatAgent、Console 和 SQLite 检查跨实例恢复、独立项目、模型无额外调用、工具仅执行一次、压缩继承、累计用量、当前护栏、同秒 ID、先锁后读、损坏审计及事务回滚。`tests/test_transcript.py` 检查切换后替换文本区且保留同一应用和草稿。

机器规范为 TR-03-R05，实际执行材料见 [2026-11-13 历史聊天验证](../../evidence/20261113-chat-resume/README.md)。这些测试验证持久化与交互机制，不代表已测完所有终端宿主或长周期磁盘故障情境。
