# ADR-0027：统一运行事件、工具窗口与游标续流

日期：2026-11-13。

状态：Accepted。

## 问题

模型 SSE 回调、注册表 `tool.start/end` 审计和协作 `revision` 分别运行。协作事件只保留最近 2000 条，Commander 定时检查 Future，工具结束前的事实缺少实时投影入口。终端通过日志字符串识别动作，只回显短摘要，普通回答却带有独立外框。

## 决定

使用标准库 SQLite 实现运行级 `EventBus`。事务先分配事件序号并持久化，再顺序投递。信封固定流、运行、任务、Worker 和调用身份，消费采用严格大于游标的读取及显式确认。重放与实时消费共用同一事件表；跨进程使用有界等待读取。

工具注册表是执行生命周期的统一生产入口；Agent 在控制器和人工审批之前发布申请，并把同一调用 ID 交给注册表。所有正常结果分支有唯一终态。外部进程沿原执行入口接入 stdout/stderr 增量，后台作业独立产生事件。现有审计链继续负责过程一致性校验。

Commander 在本线程消费 Worker 事件。工具观察实时写入 Trace，工具实际状态投影到事实图；新事实产生修订并唤醒 Planner。Future、Intent 和事实共用事件通知，DAG 依赖和能力租约规则保持原合同。

检查点事件先提交，再替换 JSON 文件。恢复读取较新的事件快照及未消费尾部，在途任务回收租约后重新尝试。事件重放本身不执行历史动作。

终端使用事件投影，按调用 ID 更新同一工具窗口。窗口包含命令或参数、Output、stderr、退出码和终态。普通正文直接使用 Markdown 排版；模型工具协议继续隐藏。聊天恢复优先重放事件，缺少完整事件的旧记录继续使用历史消息。

## 代价与边界

持久事件增加本地磁盘写入和事件库存储。当前不裁剪事件，不提供分布式消息中间件、远端 SSE 服务或任意步骤的进程续跑。消费采用至少一次语义，显示层按 `(stream_id, seq)` 去重。敏感字段脱敏不覆盖任意自由文本中的秘密。确定性 Planner 不自动生成和裁剪任意研究分支。

协议、命令及验证入口见 [统一运行事件](../../docs/EVENTS.md)。
